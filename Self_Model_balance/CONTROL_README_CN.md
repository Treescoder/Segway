# 高尔夫球车控制代码说明

## 1. 哪些文件以后需要移植到 C++

- `tracking_controller.py`：人员跟随外环，代码已按 C/C++ 写法精简。
- `segway_ball_lqr_bag_front_follow.py`：平衡、轮速和偏航内环。

以下文件只用于 MuJoCo，不需要放入嵌入式：

- `human_controller.py`：生成仿真人体轨迹和手脚动画。
- `simulate_segway_ball_buy_bag_front_follow_lqr.py`：PySide6 界面和 MuJoCo 主循环。

## 2. 实车控制器需要哪些输入

| 信号 | 来源 | 用途 |
|---|---|---|
| `human_speed` | 人员跟踪算法 | 人速前馈 |
| `human_yaw` | 人员跟踪算法 | 转弯前馈 |
| `distance` | 深度相机、双目或 UWB | 保持 1～3 m、避免撞人 |
| `bearing_error` | 人体在摄像头中的横向位置 | 让摄像头持续朝向人 |
| `cart_speed` | 车轮编码器 | 闭环跟踪人体速度 |
| `cart_yaw` | 车载 IMU | 计算车辆目标航向 |

只有人的速度和 yaw，无法知道人离车辆多远，也无法保证 1～3 m。

## 3. 为什么最终版本不使用人体加速度

早期版本用两帧速度计算人体加速度：

```text
human_accel = (human_speed - last_human_speed) / dt
```

但实测发现5 ms差分会放大视觉速度噪声和仿真步态波动，造成急走急刹。
最终控制器已经删除加速度和距离微分，只使用平滑的人速及编码器车速。

## 4. 跟随控制的三个公式

```text
速度指令 = 人的速度
         + 车速反馈系数 × (人的速度 - 实际车速)
         + 小幅距离修正

视线航向 = 车辆 yaw + 人体相对方位

目标 yaw = 视线航向
         + yaw前馈系数 × (人体 yaw - 视线航向)
```

最后对速度、距离修正和 yaw 偏移统一限幅。

## 5. 1～3 m 的量产安全说明

软件把正常目标设为 2.5 m；接近1 m时进入安全降速。

但“物理距离永远不越过 1～3 m”还取决于：

- 车辆当前速度和真实制动距离；
- 人是否突然转身朝车辆跑；
- 地面摩擦、坡度及球包质量；
- 后方是否允许车辆倒退；
- 测距延迟、丢帧和误检。

量产时必须增加独立的紧急停车层、传感器超时处理，以及倒车前的后方障碍检测。跟随控制器不能替代安全控制器。

## 6. 参数调节顺序

1. 先在低速下确认 `distance` 和 `bearing_error` 的正负方向。
2. 调 `KP_SPEED`，让编码器车速贴近人体速度。
3. 调 `KP_DISTANCE`，让距离缓慢回到 2.5 m。
4. 调 `YAW_FEEDFORWARD`，让车辆和人更同步转弯。
5. 最后才逐步提高 `MAX_SPEED`。

每次只改一个参数，并分别测试 0、3、9 kg。

## 7. LQR 移植到嵌入式时的注意事项

当前 Python 版使用 SciPy 在线求解 CARE 方程并更新 LQR 增益，适合验证，
但不建议直接照搬到 MCU。

量产版本建议在 Python 中离线计算 0～9 kg 的增益表，嵌入式仅根据球包质量
做查表或线性插值。这样不需要在 MCU 上移植 SciPy，运行时间也固定、容易测试。
